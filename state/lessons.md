## 2026-08-02, runtime: detached HEAD nearly ate a cycle's push

- The mounted repository came up with a detached HEAD at the last commit while the local main ref still pointed at an older commit. Committing normally therefore put this cycle's work on no branch, and git push origin main tried to push the stale main and was rejected as non-fast-forward. The rejection message reads like an upstream conflict, which is misleading: nothing upstream had moved.
- Diagnosis sequence that worked: git ls-remote to see the real remote tip, git for-each-ref to compare local main against HEAD, then git merge-base --is-ancestor to confirm the new commits descend from the remote tip. Fix was git branch -f main HEAD, checkout main, push.
- Standing check for every cycle before committing: confirm git rev-parse HEAD equals git rev-parse main, and if not, move the branch to HEAD first. Never resolve a non-fast-forward rejection by force-pushing; verify with ls-remote first, since the cause here was local, not remote.

## 2026-08-04, delivered copy keeps aging, and a resurfacing essay closed a lane

- Second consecutive cycle where the error was in copy already sitting in Slack, and both times the cause was the same: a claim that was true when written and false when posted. Yesterday it was "shipped today" against a Wednesday recommendation. Today it was "1,822 court decisions now deal with hallucinated AI content", where the Charlotin database updated to 1,825 on 4 August while the draft waited. Rule adopted: any number pulled from a live, continuously updated source gets a snapshot label in the copy itself, not only in the attached artifact.
